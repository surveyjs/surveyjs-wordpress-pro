# SurveyJS Forms Add-on: development

Add-on for the free **SurveyJS Forms** plugin (slug `surveyjs`). SurveyJS Forms owns all data — the forms custom post type `sjs_form` and the entries table `{prefix}sjs_results` — and exposes hooks; the add-on (slug `surveyjs-forms-addon`) adds features on top of them: Survey Creator in the form editor, PDF export, analytics, a dashboard. The add-on is downloaded from surveyjs.io or installed with Composer, and is not in the WordPress.org directory. No AI features for now.

User docs: [README.md](README.md) (install, updates; shown on GitHub and Packagist) and `readme.txt` (shown in wp-admin). This file and README.md are excluded from the zip by `.gitattributes`.

## Layout

Plugin files are at the repository root, so `git archive` gives the plugin zip and a Composer `type: wordpress-plugin` package needs no build.

| Path | What |
|---|---|
| `surveyjs-forms-addon.php` | Plugin header (`Requires Plugins: surveyjs`, `Update URI`), constants, `require`s, boot on `plugins_loaded`. |
| `includes/plugin.php` | `SurveyJS_Addon`: SurveyJS Forms version guard and its admin notice, boots the rest, fires `surveyjs_addon_loaded`. |
| `includes/install.php` | `SurveyJS_Addon_Install`: migrations on `init` by a stored version number. |
| `includes/settings.php` | `SurveyJS_Addon_Settings`: the add-on section on SurveyJS Forms' Settings page. |
| `includes/updater.php` | `SurveyJS_Addon_Updater`: the add-on follows SurveyJS Forms updates and shows the version notice (see "Updates"). |
| `includes/libs.php` | `SurveyJS_Addon_Libs`: registers/enqueues the SurveyJS libraries. |
| `includes/admin-theme.php`, `assets/admin-theme.{css,js}` | `SurveyJS_Addon_Admin_Theme`: one palette and light/dark mode for Creator, Charts and Dashboard (see "Admin colors"). |
| `includes/creator.php`, `assets/creator.js`, `assets/creator.css` | `SurveyJS_Addon_Creator`: Survey Creator in the form editor (see "Creator"). |
| `includes/analytics.php`, `assets/analytics.js`, `assets/analytics.css` | `SurveyJS_Addon_Analytics`: the Charts view of the results page. |

| `includes/pdf.php`, `assets/pdf.js`, `assets/pdf.css` | `SurveyJS_Addon_Pdf`: PDF export (see "PDF export" below). |
| `includes/pdf-respondent.php`, `assets/pdf-respondent.js` | `SurveyJS_Addon_Pdf_Respondent`: PDFs for respondents and emails (see "PDF for respondents and emails" below). |
| `includes/pdf-password.php`, `includes/pdf-encryptor.php`, `includes/pdf-aes256.php` | `SurveyJS_Addon_Pdf_Password`, `SurveyJS_Addon_Pdf_Encryptor`, `SurveyJS_Addon_Pdf_Aes256`: password-protected PDFs (see "PDF password" below). |
| `libs/` | Prebuilt library files, **committed** (git/VIP/Composer installs need no build). Generated by `npm run copy-libs`. |
| `languages/` | `surveyjs-forms-addon.pot` and translations (see "Translations"). |
| `uninstall.php` | Removes the add-on's own options only. Forms and entries belong to SurveyJS Forms. |

Constants: `SURVEYJS_ADDON_VERSION`, `SURVEYJS_ADDON_DB_VERSION`, `SURVEYJS_ADDON_MIN_BASE_VERSION`, `SURVEYJS_ADDON_LIBRARY_VERSION`, `SURVEYJS_ADDON_FILE`.

Options (all deleted by `uninstall.php`): `surveyjs_addon_settings` (array), `surveyjs_addon_db_version`, `surveyjs_addon_upgrade_lock`; site option `surveyjs_addon_update_error`. Form post meta: `_surveyjs_addon_pdf_password` (deleted with the form and by `uninstall.php`). SurveyJS Forms' uninstall with "Delete all … data" keeps every `surveyjs_addon_*` option and transient, so the add-on options and transients must use that prefix.

### Loading order and the SurveyJS Forms guard

WordPress loads `surveyjs-forms-addon/` before `surveyjs/` (alphabetical), so nothing in the add-on may touch SurveyJS Forms at file load. `SurveyJS_Addon::boot()` runs on `plugins_loaded`: if `SURVEYJS_VERSION` is missing or lower than `SURVEYJS_ADDON_MIN_BASE_VERSION`, it only adds an admin notice (`.surveyjs-forms-addon-base-notice`) and returns. Otherwise it starts install/settings and fires `surveyjs_addon_loaded`.

**Add a feature:** put it in its own file `includes/<feature>.php` with a class whose `init()` adds the hooks, end the file with `add_action( 'surveyjs_addon_loaded', array( 'SurveyJS_Addon_<Feature>', 'init' ) );`, and add one `require_once` line in `surveyjs-forms-addon.php`. Then the feature runs only when SurveyJS Forms is compatible, and parallel features touch only their own files.

### Migrations

On WordPress VIP `wpcom_vip_load_plugin()` does not fire activation hooks, so there is no activation hook. `SurveyJS_Addon_Install::maybe_upgrade()` runs on `init` (priority 1) and calls `upgrade_to_N()` for every N between the stored `surveyjs_addon_db_version` and `SURVEYJS_ADDON_DB_VERSION`, under a lock option. To add a migration: bump `SURVEYJS_ADDON_DB_VERSION` and add `private static function upgrade_to_<N>()`. Use `dbDelta()` for the add-on tables.

### Libraries

`package.json` pins exact versions. `npm run copy-libs` checks that every SurveyJS package equals `SURVEYJS_ADDON_LIBRARY_VERSION` and copies only the needed dist files into `libs/<package>/` (with each package's license file):

| Package | Version | Files in `libs/` |
|---|---|---|
| survey-creator-core | 3.2.4 | `survey-creator-core.min.js`, `survey-creator-core.min.css`, `images/`, `i18n/*.min.js` (Creator UI translations, 36 languages; `index` and `english` are skipped) |
| survey-creator-js | 3.2.4 | `survey-creator-js.min.js` |
| survey-pdf | 3.2.4 | `survey.pdf.min.js`, `spacious.min.js` (from `layouts/`, the Spacious layout preset, global `DocLayout.Spacious`) |
| survey-analytics | 3.2.4 | `survey.analytics.min.js/.css` (Chart.js) |
| jspdf | 4.2.1 | `jspdf.umd.min.js` (needed by survey-pdf) |
| chart.js | 4.6.1 | `chart.umd.min.js` (needed by survey-analytics) |
| chartjs-plugin-datalabels | 2.2.0 | `chartjs-plugin-datalabels.min.js` (optional for survey-analytics; register it with `Chart.register(ChartDataLabels)` if wanted) |

**No PHP libraries.** PDF encryption is the add-on's own code on PHP's openssl (see "PDF password").

**survey-core and survey-js-ui are not copied.** They come from SurveyJS Forms (`src/trunk/libs/library/`, v3.2.4), so a page never loads two copies of the Form Library (SurveyJS Forms' editor and results pages already load it). They are still in `package.json` to pin the peer version. SurveyJS Forms and the add-on are released with the same version, equal to the SurveyJS library version; when they differ, everything keeps working and the version notice offers to update the older plugin (see "Updates"). When SurveyJS Forms updates the Form Library, update `package.json`, `SURVEYJS_ADDON_LIBRARY_VERSION`, run `npm install && npm run copy-libs`, and release both plugins together.

To add a file (e.g. a Creator locale, plotly/apexcharts builds), add it to `FILES` in `scripts/copy-libs.js`, rerun, and register a handle in `SurveyJS_Addon_Libs`. Only these packages and their direct runtime dependencies may be read from `node_modules`.

#### PDF fonts

Not from npm: survey-pdf's own `survey.pdf.fonts.min.js` is Segoe UI, which Microsoft does not allow to redistribute, so it is not copied. The fonts are TTF files in `assets/fonts/`, fetched by `assets/pdf.js` only when a PDF needs them (URLs in `hebrewFont` / `unicodeFont` of the PDF config), each under the SIL Open Font License 1.1 with its license next to it:

| Font | Files | Used for | Source |
|---|---|---|---|
| IBM Plex Sans Hebrew | `IBMPlexSansHebrew-Regular.ttf`, `-Bold.ttf`, `OFL.txt` | text with Hebrew letters | IBM Plex |
| Noto Sans (subset) | `noto-sans/NotoSans-Regular.ttf`, `-Bold.ttf` (350 KB each), `noto-sans/OFL.txt` | any other text outside Latin-1 | Noto Sans 2.015, Noto Sans Arabic 2.013, Noto Sans Math 3.000 (unhinted TTFs from the `notofonts/latin-greek-cyrillic`, `notofonts/arabic`, `notofonts/math` GitHub releases) |

The Noto Sans files cover what survey-pdf's Segoe UI Regular covered: Latin with all extensions (Vietnamese too), IPA, Greek, Cyrillic, Arabic with its presentation forms (jsPDF shapes Arabic through them), punctuation, currency, letterlike symbols, number forms, arrows, math operators and geometric shapes. Not covered (Segoe UI had them): Coptic letters in the Greek block, the Thai baht sign, dingbat circled digits, modifier tone letters. Each weight is Noto Sans + Noto Sans Arabic of that weight + Noto Sans Math Regular (no bold exists), subset and merged with fontTools 4.55.3, without hinting and OpenType layout tables (jsPDF uses neither):

```sh
LATIN="U+0000-036F,U+0370-03FF,U+0400-052F,U+1C80-1C8F,U+1D00-1DFF,U+1E00-1EFF,U+1F00-1FFF,U+2000-218F,U+2C60-2C7F,U+2DE0-2DFF,U+2E00-2E7F,U+A640-A69F,U+A720-A7FF,U+AB30-AB6F,U+FB00-FB06,U+FE20-FE2F,U+FFFC-FFFD"
ARABIC="U+0600-06FF,U+0750-077F,U+0870-08FF,U+FB50-FDFF,U+FE70-FEFF"
MATH="U+2190-21FF,U+2200-22FF,U+25A0-25FF"
OPTS="--drop-tables+=GSUB,GPOS,GDEF,MATH --layout-features= --no-hinting --name-IDs=0,1,2,3,4,5,6"
pyftsubset NotoSansMath-Regular.ttf --unicodes="$MATH" $OPTS --output-file=math.ttf
for w in Regular Bold; do
  pyftsubset NotoSans-$w.ttf --unicodes="$LATIN" $OPTS --output-file=latin-$w.ttf
  pyftsubset NotoSansArabic-$w.ttf --unicodes="$ARABIC" $OPTS --output-file=arabic-$w.ttf
  pyftmerge latin-$w.ttf arabic-$w.ttf math.ttf --output-file=NotoSans-$w.ttf
  python -c "from fontTools.ttLib import TTFont; f = TTFont('NotoSans-$w.ttf'); f['post'].formatType = 3.0; f.save('NotoSans-$w.ttf')"
done
```

`noto-sans/OFL.txt` is the release's `OFL.txt` with the copyright lines of all three sources. The Noto fonts have no Reserved Font Name, so the subset keeps the name Noto Sans (PDF `/BaseFont` `NotoSans-Regular` / `NotoSans-Bold`).

#### PHP helper

```php
SurveyJS_Addon_Libs::enqueue( 'creator' );             // creator-core + creator-js (+ SurveyJS Forms survey-core, survey-js-ui) and CSS
SurveyJS_Addon_Libs::enqueue( 'pdf' );                 // jspdf + survey-pdf
SurveyJS_Addon_Libs::enqueue( 'analytics' );           // chart.js + datalabels + survey.analytics and CSS
```

`enqueue()` returns `false` for an unknown bundle. `script_url( $name )` returns the versioned URL of a script handle's file (for loading it on demand, e.g. `pdf-spacious`), or `''`. Call it from `admin_enqueue_scripts` or `surveyjs_admin_enqueue_scripts`. To make your own script depend on a library, call `SurveyJS_Addon_Libs::register()` (or `enqueue()`) first and use `SurveyJS_Addon_Libs::handle( $name )` as the dependency. Handles (`surveyjs-forms-addon-<name>`): `creator-core`, `creator`, `jspdf`, `pdf`, `pdf-spacious`, `chartjs`, `chartjs-datalabels`, `analytics`; styles `creator`, `analytics`.

```php
add_action( 'surveyjs_admin_enqueue_scripts', function ( $page ) {
    if ( 'surveyjs_editor' === $page && SurveyJS_Addon_Libs::enqueue( 'creator' ) ) {
        wp_enqueue_script( 'surveyjs-forms-addon-creator-tab', plugins_url( 'assets/creator-tab.js', SURVEYJS_ADDON_FILE ), array( SurveyJS_Addon_Libs::handle( 'creator' ), SurveyJS_SurveyJS::EDITOR_SCRIPT ), SURVEYJS_ADDON_VERSION, true );
    }
} );
```

### Analytics

`SurveyJS_Addon_Analytics` adds the Charts view to the results page through `surveyjs_results_views` and renders them on `surveyjs_render_results_view`; no SurveyJS Forms changes:
| View | URL | What |
|---|---|---|
| `chart` | `admin.php?page=surveyjs_results&id=<form>&view=chart` | Charts: SurveyJS Dashboard charts (`SurveyAnalytics.Dashboard`, Chart.js + datalabels) with a date range filter on the entry date. |

The view uses submitted entries only (`unread`, `read`), newest first. `assets/analytics.js` loads them in pages from `wp_ajax_surveyjs_addon_analytics_entries` (`form`, `offset`, `limit`, nonce `surveyjs-forms-addon-analytics_<form>`, capability `SurveyJS_SurveyJS::CAPABILITY`), which calls `SurveyJS_Entries::query()` with `limit`/`offset` and returns `id`, `date` (ISO 8601 UTC) and `data` (file answers with admin download URLs). Charts then work on the loaded entries in the browser. The chart layout is kept per form in the browser's `localStorage` (`surveyjs-forms-addon-<view>-<form>`).

Filters:

- `surveyjs_addon_analytics_max_entries` (default `10000`, `0` = no limit) — how many of the latest entries the view loads. Above it the view says "Showing the latest N of M entries"; Export CSV still has all of them.
- `surveyjs_addon_analytics_page_size` (default `500`) — entries per AJAX request.

### Dashboard

`SurveyJS_Addon_Dashboard` adds SurveyJS Forms > Dashboard (`admin.php?page=surveyjs-forms-addon-dashboard[&range=7d|30d|90d|12m]`, default `30d`) through `surveyjs_admin_menu`, at position 3 of the submenu: after All Forms, Add New Form and Entries, before Settings and Support. Across all published forms it shows: entries in the period (with the change vs the previous period of the same length), all entries, unread, number of forms; a bar chart of entries per day (per month for `12m`) and a horizontal bar chart of entries per form in the period (top 10 + "Other", a bar opens the form's results); the 10 latest entries (link opens the entry on the results page via `&entry=<id>`); a table of forms that have entries or views (period, all, unread, views, conversion, last entry) with totals. When SurveyJS Forms counts form views (`SurveyJS_Form_Stats::enabled()`), it also shows views (with the change vs the previous period) and conversion (submissions ÷ views) for the period, and a "Views and submissions" bar chart per day/month with the conversion in the tooltip; with the setting off, the panel links to Settings instead. Views and submissions come from SurveyJS Forms' daily `sjs_form_stats` rows (two `GROUP BY form_id` queries for the period and the previous one, one `GROUP BY` bucket for the chart), so the submissions behind conversion are counted events, not stored entries: they include forms that don't store entries and are not reduced when entries are deleted or marked as spam.

Counts are submitted entries only (`unread`, `read`); partial and spam are left out. Every query is an aggregate or `LIMIT` over SurveyJS Forms' `form_status_date` index, so no entry JSON is loaded: per-form counts are one `GROUP BY form_id, status`; the chart is one `GROUP BY` day/month over the period, shifted by the site's current UTC offset (`CONVERT_TZ()` needs MySQL time zone tables, often missing); latest entries are a `UNION ALL` of per-form/status `ORDER BY created_at DESC LIMIT 10` subqueries (in chunks of 100), each read in index order. Charts use Chart.js from `libs/` (handle `surveyjs-forms-addon-chartjs`).

### Admin colors

Creator, Charts and Dashboard take every color from one place, `assets/admin-theme.css`: `--wp-sjs-addon-*` tokens on `body` (accent, surfaces, text, borders, grid, inputs, chart colors 1–10 and their label colors, font), redefined under `html.wp-sjs-addon-dark`. A designer changes colors only there. The accent is `--wp-admin-theme-color`, which WordPress sets for the user's admin color scheme (Users > Profile); in dark mode its lightness is raised for contrast. Chart color 1 is the accent, 2–10 a fixed categorical palette (checked for color-blind separation in both modes).

`assets/admin-theme.js` (handle `surveyjs-forms-addon-admin-theme`, in the head) sets `html.wp-sjs-addon-dark` and exposes `window.surveyjsAddonAdminTheme`: `isDark()`, `color( token )` (resolved `rgba()`, for canvas charts), `surveyjsTheme()` (a SurveyJS theme whose `--sjs2-*` variables point to the tokens; passed to `creator.applyCreatorTheme()` and to `applyTheme()` of the SurveyJS Dashboard) and `onChange( callback )` (also the `surveyjs-forms-addon:admin-theme` event on `document`). Pages switch live, without a reload, and Chart.js / survey-analytics charts are redrawn. To theme a new add-on page: call `SurveyJS_Addon_Admin_Theme::enqueue()`, depend on its handle, use the tokens in CSS.

Color mode — Settings → Add-on → "Color mode" (`surveyjs_addon_settings[admin_theme]`, filter `surveyjs_addon_admin_theme_mode`):

- `auto` (default) — match the WordPress admin. Core has no dark admin, so dark comes from dark mode plugins; they all repaint the admin background, so the add-on checks the first opaque background behind `#wpbody-content` (luminance < 0.2) and re-checks when `html`/`body` classes or styles change (plugin toggles) and on `prefers-color-scheme` changes. Filter `surveyjs_addon_admin_theme_dark_selectors` adds CSS selectors that mean "dark" (for plugins that darken without repainting the background).
- `system` — the device setting (`prefers-color-scheme`).
- `light`, `dark` — fixed. With `dark` and a light admin only the add-on's own parts turn dark.

### Settings

`SurveyJS_Addon_Settings` registers the option `surveyjs_addon_settings` in SurveyJS Forms' option group, so it is saved by SurveyJS Forms' Settings form (SurveyJS Forms > Settings, Add-on tab). Every section that is not SurveyJS Forms' goes to the Add-on tab, and saving that tab saves only the options of the group other than SurveyJS Forms' `surveyjs-settings` (the General and Spam Protection tabs save only `surveyjs-settings`), so a tab never empties the options of another. API: `SurveyJS_Addon_Settings::all()` (only the keys of `defaults()`), `update( array $values )`, `defaults()`. To add a global the add-on setting: add its key to `defaults()`, sanitize it in `sanitize()`, and add a field in `register()` (or your own section on `surveyjs_register_settings`).

### Updates

SurveyJS Forms (wordpress.org) and the add-on (surveyjs.io) are released together, with the same version as the SurveyJS library. Release order: first upload the add-on zip to `https://cdn.surveyjs.io/wordpress/surveyjs-forms-addon.zip` (fixed URL, always the latest add-on, one top folder `surveyjs-forms-addon/`), then release SurveyJS Forms on wordpress.org. There is no info API: the add-on always installs the latest zip ("we guarantee no breaking changes").

- **The add-on follows SurveyJS Forms.** `upgrader_process_complete` with `type` `plugin`, `action` `update` and `surveyjs/surveyjs.php` in `plugin`/`plugins` (single, bulk, Ajax and core background auto-updates) adds `SurveyJS_Addon_Updater::follow_base()` to `shutdown` of the same request: core's upgrader still has its filters for SurveyJS Forms attached during `upgrader_process_complete`, and a failed auto-update is rolled back only after it. `follow_base()` calls `update()` only when the SurveyJS Forms version on disk differs from the loaded `SURVEYJS_VERSION` (so not after a failed or rolled-back update). `update()` downloads the zip with `wp_safe_remote_get()` (user agent `SurveyJS-Forms-Addon/<version>`, no site URL) and installs it over itself with `Plugin_Upgrader::install( $file, overwrite_package )` and `Automatic_Upgrader_Skin` (no output; same filesystem credentials as the SurveyJS Forms update: `FS_METHOD`/`FTP_*` constants or the credentials posted with it). The plugin is not deactivated, so it stays active. A failure never affects the SurveyJS Forms update: its message is stored in the site option `surveyjs_addon_update_error` and shown in the version notice; a success deletes it.
- **Version notice** (`.surveyjs-forms-addon-version-notice`, all admin pages, users with `update_plugins`; with `DISALLOW_FILE_MODS` users with `activate_plugins`, text only). Shown when `SURVEYJS_VERSION` differs from `SURVEYJS_ADDON_VERSION`; one button, for the older plugin only. SurveyJS Forms older (the normal case): title "Please update SurveyJS Forms", button "Update SurveyJS Forms" (core's `update.php?action=upgrade-plugin` link when core knows a SurveyJS Forms update, otherwise `plugins.php`). The add-on older (the follow step failed, or an old add-on zip was installed): title and button "Update SurveyJS Forms Add-on" (`admin-post.php?action=surveyjs_addon_update`, nonce, runs the same `update()`). Nothing is turned off on a mismatch. A SurveyJS Forms older than `SURVEYJS_ADDON_MIN_BASE_VERSION` (no add-on contract yet) gets the same notice; the add-on itself does not boot then.
- **Off** (`SurveyJS_Addon_Updater::enabled()`): always on VIP (`WPCOM_IS_VIP_ENV`, `VIP_GO_APP_ENVIRONMENT`), with `SURVEYJS_ADDON_DISABLE_UPDATES` true and when `wp_is_file_mod_allowed( 'surveyjs_addon_self_update' )` is false; otherwise the filter `surveyjs_addon_self_update` (`bool`) decides, with default `false` on a Composer install. `SURVEYJS_ADDON_DISABLE_UPDATES` defined as `false` makes the default `true` even on a Composer install. When off, the add-on never downloads and the notice has no add-on button.
- **Composer install** (`SurveyJS_Addon_Updater::composer()`, once per request): true only when Composer's records put `surveyjs/surveyjs-forms-addon` in the real path of the add-on's own folder — `Composer\InstalledVersions::getInstallPath()` when the project's autoloader is loaded (Bedrock), otherwise `<vendor-dir>/composer/installed.json` (`install-path` is relative to that folder) next to a `composer.json` in up to `COMPOSER_ROOT_DEPTH` (4) parent folders: classic `wp-content/plugins/x` → root is 3 up, Bedrock `web/app/plugins/x` → 4 up, `vendor/surveyjs/x` → 3 up. A bare `composer.json`, a `vendor/` folder or an install path pointing elsewhere don't count, and folders outside `open_basedir` are not touched. Composer's dist has no `composer.json` (`export-ignore`), so the plugin folder itself is never checked. `managed_by_composer()` (Composer install and self-update off) adds the note to the add-on's row meta on Plugins (`.surveyjs-forms-addon-composer-note`), replaces "will be updated to the same version automatically" in SurveyJS Forms' update row and the add-on buttons in the version notice with the `composer update surveyjs/surveyjs-forms-addon --with-dependencies` hint. Tests: `tests/e2e/composer.spec.js` fakes `composer.json` and `vendor/composer/installed.json` in the container.
- **`Update URI: https://surveyjs.io/wordpress-addon`** keeps wordpress.org from offering a foreign `surveyjs-forms-addon` from its directory as an update. The add-on hooks nothing for it, so core shows no add-on updates in Plugins.
- **Multisite:** network-activate the add-on; core updates plugins in Network Admin and runs auto-updates on the main site, and the add-on must be loaded there.

### Creator

Survey Creator V3 replaces the JSON editing in SurveyJS Forms' form editor (Edit button on All Forms). It uses only SurveyJS Forms hooks, SurveyJS Forms needs no changes for it.

- **Tabs.** `surveyjs_editor_tabs`: replaces `survey` (Config) with `creator`, labelled "Config" as in SurveyJS Forms, as the first tab — people find the same tabs, only the content changes. `theme` (Adaptive mode, ready-made themes, AI theme prompt, theme JSON), `email`, `entries`, `spam` (Spam Protection) and `advanced` (Save & Resume, Markdown; SurveyJS Forms keeps it the last tab, after PDF) stay. The panel (`surveyjs_render_editor`) is `.wp-sjs-addon-creator[data-panel="creator"]`; on that tab SurveyJS Forms' preview is hidden and the panel takes the full width.
- **Language.** Creator UI follows the admin language (`determine_locale()`): `SurveyJS_Addon_Creator::LOCALES` maps the WordPress language (or `zh_CN`/`zh_TW`-style locale) to a file in `libs/survey-creator-core/i18n/` and the Creator locale code; the file is enqueued as `surveyjs-forms-addon-creator-i18n` and `creator.locale` is set. Languages without a file stay English. RTL comes from the admin page (`dir="rtl"` on `<html>`), Creator inherits it.
- **Creator tabs:** Designer, Preview, Logic, JSON Editor, Translations. Creator's Themes tab is off: the theme is set in SurveyJS Forms' Theme tab, whose preview shows the form on a real page of the site. No AI. Creator's own theme settings (the gear at the bottom of the side bar, `showCreatorThemeSettings`) are off too: Creator follows the admin color scheme and Color mode, and changes made there would not be kept.
- **Setting.** "Edit forms in Survey Creator" in Settings → Add-on (`surveyjs_addon_settings[creator]`, on by default) is the default value of `surveyjs_addon_creator_enabled`; off brings back SurveyJS Forms' Config tab. The add-on passes it to `surveyjs_visual_editor_enabled`, so SurveyJS Forms' blank-form texts and empty-form hint follow it too (`tests/e2e/visual-editor.spec.js`).
- **Look.** "Match the WordPress admin style" in Settings → Add-on → "Survey Creator style" (`surveyjs_addon_settings[admin_style]`, on by default). On, Creator gets the admin colors and WordPress admin sizes through its theme: `creator.css` defines `--wp-sjs-addon-creator-unit-*` (base units for sizes, spacing, font size, line height, corner radius; Creator's default is 8px each) and small-text sizes, `creator.js` resolves them and passes them to `applyCreatorTheme()` with the admin colors, plus white inputs with the admin's input border (`--wp-sjs-addon-input-bg`, `--wp-sjs-addon-input-border` from `admin-theme.css`). Result: 13px text, 2px corners, outlined inputs, like the admin's own forms. Creator applies its theme to the Designer canvas too, so the canvas is a plain, compact draft of the form; how the form really looks is on the Preview tab (the site page). Off, `creator.js` applies Creator's default theme (`adminStyle` is false in `window.surveyjsAddonCreator`); Creator has no default dark theme of its own, so in dark mode it gets SurveyJS Forms' `default-dark` preset (`darkTheme`). Color mode works either way.
- **JSON issues.** On `surveyjs:editor-review-issues` the add-on cancels the event, switches to the Creator tab and its JSON Editor tab (`creator.switchTab( "json" )`) and calls `model.gotoError()` for the matching entry of `creator.getPlugin( "json" ).model.errorList` (same as clicking it), retrying until Creator has rendered and linted the text. Creator's lint options go to SurveyJS Forms through `surveyjsEditor.setLintOptions()`.
- **Sync with SurveyJS Forms.** Creator is built when its tab is first shown, from `surveyjsEditor.getSurvey()` / `getTheme()`. Creator autosave (`isAutoSave`, `autoSaveDelay = 0`) does not save anything: `saveSurveyFunc` / `saveThemeFunc` call `surveyjsEditor.setSurvey()` / `setTheme()` on every change, so SurveyJS Forms' Save button, unsaved-changes prompt, Reply-To/File pickers and preview see Creator's changes. When the Creator tab is shown again, the survey and theme are reloaded into Creator if they changed in SurveyJS Forms meanwhile (theme JSON in the Theme tab, "Add a Reply-To question" in Email). Text typed in Creator's JSON Editor tab is applied before SurveyJS Forms' Save, before a SurveyJS Forms tab switch and before the page unloads. When the theme is changed in Creator while Adaptive is on, Creator shows a notice that the site uses the Adaptive styles.
- **GDPR Agreement question.** A toolbox item at the end of Creator's toolbox (`toolbox.addItem`, name `gdpr_agreement`) that adds SurveyJS Forms' GDPR question: a required boolean shown as a checkbox, text and error from `surveyjsEditor.config.gdpr`. It is a plain `boolean`, so nothing has to be registered on the site to render it. Its icon is the boolean question's for now.
- **Images.** Creator's file choosers open the WordPress Media Library (`wp.media`); files dropped into Creator are uploaded to the Media Library through the REST API (`wp-api-fetch`, `/wp/v2/media`). The survey JSON keeps the attachment URL.
- **Full screen.** A "Full screen" button next to Save, on by default. It hides the admin bar, the admin menu and the footer and makes `.wp-sjs-editor` a fixed full-window layer (`z-index: 1000`, below SurveyJS popups); all form editor tabs work in it. Turning it off is remembered per browser in `localStorage` (`surveyjs-forms-addon-editor-fullscreen`).
- **Preview tab.** SurveyJS Forms' preview frame (the form on the site's preview page) is laid over the canvas of Creator's Preview tab (`.svc-test-tab__content`), placed by `getBoundingClientRect` and kept in place on tab, layout (`isMobileView`), size and scroll changes. Creator's preview toolbar works on it: with a device picked (iPhone, iPad, Android, Surface) the frame is laid over the simulator's screen (`.svd-simulator-content`) at the device's CSS size from `creator.getPlugin("preview").model.simulator.simulatorFrame` (`deviceWidth` / `deviceHeight`, landscape included), scaled like the simulator and clipped to the canvas, so the site theme shows its real breakpoints; "Show invisible elements" (the eye) calls `surveyjsEditor.setPreviewShowInvisibleElements()`, and leaving the Preview tab turns it off again. While SurveyJS Forms' full preview is open (`surveyjs:editor-full-preview`), the overlay steps aside.
- **WordPress admin CSS.** `creator.css` resets the admin's `input[type=text]`, checkbox and `li` styles inside `.svc-creator` and `.sv-popup` (same approach as SurveyJS Forms' `survey.css`).
- **Off switch.** `add_filter( 'surveyjs_addon_creator_enabled', '__return_false' )` keeps SurveyJS Forms' JSON editor (e.g. for SurveyJS Forms' e2e tests, which expect Monaco on the first tab). Creator is also off when the libraries don't match SurveyJS Forms' Form Library version.

### PDF export

`SurveyJS_Addon_Pdf` (`includes/pdf.php`) uses only the SurveyJS Forms hooks below; SurveyJS Forms has no PDF code.

- **Editor:** tab `pdf` (`surveyjs_editor_tabs` + `surveyjs_render_editor`) with per-form settings; buttons "Preview PDF" and "Download blank form" use the unsaved JSON, theme and settings from `window.surveyjsEditor`. A live preview of the blank form (`<iframe>` with a blob URL, the browser's PDF viewer, `assets/pdf.css`) sits right of the settings, below them under 1280 px; it is rebuilt 500 ms after an input/change on the tab and when the tab opens (`surveyjs:editor-tab`), only while the tab is visible; stale results are dropped and errors go to the status line, keeping the last preview. PDFs on the editor page render one at a time.
- **Per-form settings** (`surveyjs_form_settings_defaults` / `_sanitize`): `addonPdfFormat` (`auto` default, `a4`, `letter`, `legal`, `a3`, `a5`), `addonPdfOrientation` (`portrait` default, `landscape`), `addonPdfFontSize` (8–24, default 14), `addonPdfLabelFontSize` (8–24, default 14; question titles are scaled by `addonPdfLabelFontSize / addonPdfFontSize` in `onGetQuestionStyle`, so equal values keep survey-pdf's proportions), `addonPdfLayout` (`compact`/`spacious`), `addonPdfFont` (`helvetica` default, `times`, `courier`: jsPDF's standard fonts, used while the text fits Latin-1), `addonPdfThemeColors` (apply the form's SurveyJS theme when Adaptive is off and the theme is not dark), `addonPdfAccent` + `addonPdfAccentColor` (off by default; `#rrggbb`, default `#19b394`, the SurveyJS brand color), `addonPdfFillable` (blank form as AcroForm), `addonPdfEntryHeader` (entry ID and date in the top margin), `addonPdfPageNumbers`, `addonPdfLogo` (Media Library attachment ID, `0` = none; the editor and results page get its `large` URL as `logo.url`; "Use site logo" picks the theme's custom logo, the block theme's site logo or the site icon, in that order, as `site.logo` in the editor config), `addonPdfHeaderText` (up to 100 characters; "Use site title" fills it with the site title), `addonPdfFooterText` (up to 100 characters), `addonPdfFooterDate` (the date the PDF is made, in the site language), `addonPdfWatermark` (up to 40 characters, empty = none), `addonPdfHideEmpty` (entry PDFs leave out unanswered questions).
- **Results page:** title action "Blank Form PDF" (`surveyjs_results_title_actions`), row action `pdf` after `view` (`surveyjs_entry_row_actions`), bulk action `addon_pdf` "Export PDF" before `delete` (`surveyjs_entries_bulk_actions`). `assets/pdf.js` intercepts the bulk form submit; if the request still reaches the server, `surveyjs_entries_bulk_action_addon_pdf` redirects back with `&addon_pdf=<ids>` and the page starts the export on load. One entry gives `<form>-entry-<id>.pdf`, several give `<form>-entries.zip` (one PDF per entry, ZIP built in the browser, no compression).
- **Data:** `admin-ajax.php?action=surveyjs_addon_pdf_entries` (POST `form`, `entries[]` up to 500, nonce `surveyjs-forms-addon-pdf_<form>`, capability `SurveyJS_SurveyJS::CAPABILITY`) returns `id`, `date` (`SurveyJS_Entries::format_date`) and `data` (with admin file URLs) of entries of any status.
- **Rendering** (`assets/pdf.js`, all in the browser): entries are read-only (`readonlyRenderAs: "text"`, compressed); the blank form is fillable unless `addonPdfFillable` is off — fillable PDFs are not compressed because jsPDF drops AcroForm fields of a compressed document. The blank form shows every question, including conditional ones (`dynamicContent`: conditional elements, choices, matrix rows/columns, choice comments and nested content), because a printed form has no logic. `[text](url)` in form texts is printed as `text`. Pages are portrait or landscape by `addonPdfOrientation` (`orientation` `"p"`/`"l"` is always passed: survey-pdf 3.2.2 makes a page given by a format name landscape otherwise) with 10 mm margins; with `addonPdfFormat` `auto` the page size is Letter for the site locales of the US, Canada and Latin American Letter countries and A4 otherwise (`SurveyJS_Addon_Pdf::page_format()`, filter `surveyjs_addon_pdf_page_format`, any jsPDF format). The font is `addonPdfFont` (Helvetica by default) unless the form, the answers, the header or the footer have characters outside Latin-1; then Noto Sans (`assets/fonts/noto-sans/`) is fetched on demand and registered with `SurveyPDF.DocController.addFont` as `NotoSans`; text with Hebrew letters uses IBM Plex Sans Hebrew (`assets/fonts/`) the same way (see "PDF fonts"). The Spacious preset is applied without its page paddings so the 10 mm margins still apply. With a logo or header text the top margin is 24 mm: `onRenderHeader` draws the logo (downscaled in the browser to fit 50 × 12 mm, PNG data URL) and the header text on the left; the entry header (number and date) is drawn on the left of the footer, page numbers on the right, so the header area stays free for the logo and the survey-pdf license banner. With footer text or the date the bottom margin is 16 mm: that text is centered on the upper line, the entry header and page numbers move to the lower line. The accent color replaces `--sjs2-color-project-brand-600` (selected choices) through `applyTheme( { cssVariables }, formTheme )`, so it also wins over "Use the colors of the form theme"; the form, page and panel titles get it through `applyStyle` only when its contrast with white is at least 3:1; with a logo or header text a 1.5 pt accent line (a PNG drawn with `drawImage({ rect })`, since `DrawCanvas` has no line or color API: `drawText` always uses `#404040`) is drawn 3.5 mm above the content. The watermark is a semi-transparent PNG drawn in the browser (canvas, rotated text) and placed over each page with `onRenderFooter` + `drawImage({ rect })`; jsPDF embeds it once per PDF. "Leave out unanswered questions" sets `visible = false` on input questions whose value and comment are empty after the entry data is loaded; panels and pages left empty disappear with them. jsPDF's own `encryption` option is not used: survey-pdf creates the jsPDF document without it, and it is 40-bit RC4 only; passwords are added on the server (see "PDF password").

### PDF for respondents and emails

`SurveyJS_Addon_Pdf_Respondent` (`includes/pdf-respondent.php`, `assets/pdf-respondent.js`) adds the "After submit" row to the PDF tab through the add-on's action `surveyjs_addon_pdf_editor_rows` (argument: the form `$survey`; fires inside the tab's `<table class="form-table">`, before the Export row), the "PDF Attachment" rows and the "PDF Link in Emails" group to the Email tab through SurveyJS Forms' `surveyjs_editor_email_rows`, and works only through the SurveyJS Forms hooks below. All PDFs are made in the browser by `createPdf` of `assets/pdf.js`, which exposes `window.SurveyJSAddonPdf = { createPdf, download, fileBase }`; its `config.page` is `front` there, so it runs neither the editor nor the results code.

- **Per-form settings** (all off by default): `addonPdfDownload`, `addonPdfAttachNotification`, `addonPdfAttachAutoReply`, `addonPdfEmailLink`, `addonPdfLinkDays` (0–365, default 30, 0 = no expiry).
- **Front end.** For a form with `addonPdfDownload` or an attachment option on (and that email on), `surveyjs_enqueue_form_assets` enqueues `pdf-respondent.js` (footer, a few KB, depends on survey-core) and `surveyjs_form_client_config` adds `addonPdf` (`download`, `attach`, `settings`) to the form config. jsPDF, survey-pdf, the Spacious preset and `pdf.js` (~1 MB) are loaded on demand, in that order, by URL from `SurveyJS_Addon_Libs::script_url()`; the Noto Sans or IBM Plex Sans Hebrew font files only when the PDF needs them.
- **Download PDF after submit.** On `surveyjs:submitted` a button `.wp-sjs-addon-pdf-download button` (class `wp-element-button`) is added after the form; a click loads the libraries and downloads `<form title>-entry-<id>.pdf` built from the respondent's answers. `surveyjs_save_result_response` returns `addonPdf: { id, date }` for the entry header (no header when entries are not stored).
- **Attachment.** On `surveyjs:before-submit` the browser builds the PDF and adds it as the file field `AddonPdf` (SurveyJS Forms then sends multipart). If it is not ready in 20 s, fails, or is over the size limit (`surveyjs_addon_pdf_attachment_max_size`, default 10 MB, capped by `wp_max_upload_size()` and by `post_max_size` together with the answers) the entry is sent without it. The server (`surveyjs_notification_attachments`) accepts it only in the `SurveyJS_SaveResult` request (nonce already checked by SurveyJS Forms), only for the recipient whose option is on, only a real upload within the size limit that starts with `%PDF-`; it is moved to `get_temp_dir()` under a random name, attached as `<form>-entry-<id>.pdf` (skipped if the email would exceed `SurveyJS_Notification::MAX_ATTACHMENTS_SIZE`) and deleted a day later by a one-off cron event (`surveyjs_addon_delete_pdf`), so mail plugins that queue emails still find it. The PDF is made by the respondent's browser, so it can be crafted; the stored entry stays the source of truth.
- **Link in emails.** Mail tags `{pdf_link}` (HTML: a "Download PDF" link; text: the URL) and `{pdf_url}` (the URL) through `surveyjs_notification_tags`; empty unless `addonPdfEmailLink` is on and the entry is stored. The URL is `home_url( '/?surveyjs_pdf=<form>.<entry>.<expires>.<signature>' )`, signature = HMAC-SHA256 of `surveyjs-forms-addon-pdf|form|entry|expires` with `wp_salt( 'auth' )` (`SurveyJS_Addon_Pdf_Respondent::link_url()`). On `template_redirect` the page checks the signature, the expiry (users with `SurveyJS_SurveyJS::CAPABILITY` may open expired links), that the form is published and still has `addonPdfEmailLink` on, then prints a standalone page (`noindex`, `no-referrer`, no cache) with that entry only; the browser builds the PDF, shows it in a frame and offers Download PDF. File answers get admin URLs for admins and 24-hour signed URLs otherwise. Changing the salts or turning the option off invalidates all links.

### PDF password

`SurveyJS_Addon_Pdf_Password` (`includes/pdf-password.php`) adds two rows to the PDF tab through `surveyjs_addon_pdf_editor_rows` (after "After submit"): the per-form setting `addonPdfPassword` ("Password protect PDF", off by default; not in `SurveyJS_Addon_Pdf::pdf_defaults()`, so it never reaches the respondent's page) and a `type=password` field. when `available()` is false (PHP < 8.2 or no openssl/ctype — the plugin header already requires PHP 8.2) the checkbox is disabled with a note.

- **Storage.** One password per form, in the form's post meta `_surveyjs_addon_pdf_password`: AES-256-GCM with a key derived from `wp_salt( 'auth' )` and the form ID as associated data (base64 of IV, tag and ciphertext). It is never printed: the field is always empty, with the placeholder "Password is set". The password is NFKC-normalized (the part of SASLprep that PDF readers apply to the typed password), 1–127 bytes, without control characters. New salts make the stored password unreadable, which counts as "no password".
- **Saving.** The field has no `data-setting`, so it is neither in `Settings` of SurveyJS Forms' save request nor in `window.surveyjsEditor.getSettings()`. After SurveyJS Forms' save (`surveyjs:editor-saved`) `assets/pdf.js` posts to `admin-ajax.php?action=surveyjs_addon_pdf_password` (POST `form`, `password` or `remove=1`, nonce `surveyjs-forms-addon-pdf_<form>`, capability `SurveyJS_SurveyJS::CAPABILITY`): option on and the field filled sets the password, option on and the field empty keeps it, option off deletes it. The result goes to the tab's status line. Typing only in the field does not make the editor "dirty".
- **Which PDFs.** With `addonPdfPassword` on, every PDF of the form that an admin gets is encrypted: the entry PDF, each PDF in the bulk ZIP, Blank Form PDF on the Results page, "Download blank form" on the PDF tab (when the checkbox is on there, saved or not; with a typed but unsaved password it refuses), and the PDF attached to the email notification (a separate encrypted copy in `get_temp_dir()`, deleted a day later like the original). Not encrypted: the live preview and "Preview PDF" on the PDF tab, the respondent's Download PDF button, the auto-reply attachment and the `{pdf_link}` page. With the option on and no password, admin downloads fail with a message and the notification goes out without the PDF.
- **Admin flow.** The browser builds the PDF as before, then `fetch` POSTs it as the raw body (`Content-Type: application/pdf`) to `admin-ajax.php?action=surveyjs_addon_pdf_encrypt&form=<id>&_ajax_nonce=<nonce>` (`window.surveyjsAddonPdf.password.encryptUrl`). The server checks the nonce and the capability, reads `php://input` up to `surveyjs_addon_pdf_encrypt_max_size` (filter, default 32 MB), requires `%PDF-`, encrypts and answers `application/pdf` with `Cache-Control: no-store`. Errors are JSON `{ success: false, data: { message } }` — 400 not a PDF, 403, 404, 409 no password set, 413 too large, 422 not encryptable — and are shown in the status line; nothing is downloaded then. The ZIP is still built in the browser, one request per PDF.
- **Email.** `SurveyJS_Addon_Pdf_Respondent::notification_attachments()` swaps the owner's attachment for `SurveyJS_Addon_Pdf_Password::encrypted_copy()`; without a password or when encryption fails, the owner's email is sent without the PDF.
- **Encryption** (`SurveyJS_Addon_Pdf_Encryptor::encrypt( $pdf, $password )`, no WordPress calls except `esc_html()` on the values in exception messages, throws on failure). AES-256, security handler revision 6 (`/V 5 /R 6`, `/AESV3`, ISO 32000-2) in `SurveyJS_Addon_Pdf_Aes256` on PHP's openssl: a random 256-bit file key from `random_bytes()`, `/U` `/UE` `/O` `/OE` with the Algorithm 2.B hash, `/Perms`, `/EncryptMetadata true`; the password is cut to 127 bytes; random owner password; all permissions allowed (`/P -4`). The document is rewritten object by object, not re-rendered, so text, fonts, links, outlines and AcroForm fields stay as they are. A tokenizer parses each object (literal strings with escapes, nested parentheses and line breaks, hex strings, names with `#xx`, dictionaries, arrays, references, comments) and writes it back with every string encrypted with the file key (AES-256-CBC, a random IV per string and stream); stream data is encrypted as is and gets a direct `/Length` (an indirect `/Length` is resolved first). The output is `%PDF-1.7` with `/Extensions << /ADBE << /BaseVersion /1.7 /ExtensionLevel 8 >> >>` in the catalog, a new classic xref table and a trailer with `/Encrypt` and the original `/ID` (random if missing). Only what jsPDF writes is accepted: a cross-reference or object stream, `/Prev` or `/XRefStm` (incremental updates), an existing `/Encrypt`, a `/Length` that does not match its stream, an object not at its xref offset or broken syntax throws `UnexpectedValueException` instead of producing a damaged file. Checked with qpdf 11.9 (`--check`; the user and owner passwords open it, a wrong password is rejected), poppler 24.02 (same text and rendering as the original), Ghostscript 10.05 and pdf.js, on compressed and uncompressed jsPDF output with links, AcroForm fields, document info, and Cyrillic and Hebrew text in an embedded font; browsers, Acrobat and Preview were not checked. poppler's command-line tools reject passwords longer than 32 bytes in any R6 file (also in files qpdf encrypts itself); qpdf, Ghostscript and pdf.js accept them up to 127 bytes.

## Translations

The add-on is not on wordpress.org, so translate.wordpress.org gives it no language packs. All the add-on strings use the text domain `surveyjs-forms-addon` (headers `Text Domain: surveyjs-forms-addon`, `Domain Path: /languages`). The SurveyJS libraries (Creator, Dashboard, PDF) bring their own locales; they are translated in the SurveyJS repositories, not here.

- **Template.** `languages/surveyjs-forms-addon.pot` holds every PHP string and the plugin header. Regenerate it with `npm run make-pot` (`wp i18n make-pot` in the official `wordpress:cli` Docker image) when strings change, at least before each release.
- **Translators.** Copy the `.pot` to `languages/surveyjs-forms-addon-<locale>.po` (e.g. `surveyjs-forms-addon-de_DE.po`), translate it in Poedit or Loco Translate, keep the placeholders (`%s`, `%1$s`) and read the `translators:` comments. Compile with `wp i18n make-mo languages` (optionally `wp i18n make-php languages` for the faster `.l10n.php`). Commit `.po` and `.mo`; they ship with the next release.
- **JavaScript.** the add-on scripts don't use `wp.i18n`: PHP translates their strings and passes them in the `window.surveyjsAddon*` configs, so there are no `.json` translation files and no `wp_set_script_translations()`. Add new script strings the same way.
- **Site overrides.** `wp-content/languages/plugins/surveyjs-forms-addon-<locale>.mo` (or `.l10n.php`) replaces the bundled file of that locale completely: WordPress loads only the first file it finds.
- **Loading.** WordPress 6.8+ registers `Domain Path` itself when it loads the plugin; for 6.5–6.7 `SurveyJS_Addon::load_textdomain()` calls `load_plugin_textdomain()` on `init`. Translations load just in time in the user's admin language. Don't call `__()` before `init`.
- **Test.** `tests/e2e/i18n.spec.js` copies `tests/e2e/fixtures/surveyjs-forms-addon-de_DE.l10n.php` into `languages/`, switches the admin user to `de_DE` and checks PHP strings, the menu, the plugin description and a Creator toolbar label (needs `WP_CONTAINER`).

## Releasing

### Composer and Packagist

User side: [README.md → Install with Composer](README.md#install-with-composer).

- Check: `composer validate --no-check-lock` (e.g. `docker run --rm -v "$PWD:/app" composer:2 composer validate --no-check-lock`). Not `--strict`: the exact `wp-plugin/surveyjs` constraint is deliberate and is reported as a warning ("exact version constraints … should be avoided").
- `composer.json` has no `version`: Packagist takes it from the git tag, so the tag (`3.2.4` or `v3.2.4`) must equal `Version:` in `surveyjs-forms-addon.php`. On each release bump the `wp-plugin/surveyjs` constraint in `composer.json` together with `SURVEYJS_ADDON_VERSION` and `SURVEYJS_ADDON_MIN_BASE_VERSION`.
- Packagist reads `composer.json` from the tag, and the installed files come from GitHub's archive of the tag, which honors `export-ignore` in `.gitattributes`: the Composer install has the same files as the Upload zip (no `composer.json`, `tests/`, `scripts/`, `package.json`). `--prefer-source` clones the whole repository instead.
- Packagist setup: the GitHub repository must be public, then submit it at https://packagist.org/packages/submit and keep the GitHub hook (Packagist's GitHub app or a webhook to `https://packagist.org/api/github`) so new tags appear automatically.

### Building the zips

`npm run build -- [options]` (`scripts/build.js`, Node 22.2+, no dependencies) builds into `dist/` (gitignored):

- `surveyjs-forms-addon-<version>.zip` — `git archive --prefix=surveyjs-forms-addon/` of `--ref` (default `HEAD`), so `export-ignore` in `.gitattributes` applies (`vip/`, `scripts/`, `tests/`, … are left out);
- `surveyjs-forms-vip-<version>.zip` — SurveyJS Forms in `plugins/surveyjs/`, the same add-on files in `plugins/surveyjs-forms-addon/`, and `vip/client-mu-plugins/surveyjs-forms.php` of the same ref as `client-mu-plugins/surveyjs-forms.php`;
- `SHA256SUMS` for both.

SurveyJS Forms for the VIP archive: by default the wordpress.org zip of the same version (`https://downloads.wordpress.org/plugin/surveyjs.<version>.zip`), so the archive has exactly the released SurveyJS Forms. Before SurveyJS Forms is on wordpress.org: `--base-ref <rev>` (`src/trunk` of `../surveyjs-wordpress` at that commit; `--base-repo <dir>` for another checkout), `--base-worktree`, or `--base-zip <file|url>`. `--worktree` builds the add-on from the working tree (uncommitted and untracked files, minus `.gitignore`) for local testing. The build stops when `Version`, `SURVEYJS_ADDON_VERSION` and `Stable tag` differ, when SurveyJS Forms is older than `SURVEYJS_ADDON_MIN_BASE_VERSION` or ships another SurveyJS library than `SURVEYJS_ADDON_LIBRARY_VERSION`, and when a development file ends up in the add-on zip. Release: `npm run build -- --ref <tag>` after SurveyJS Forms is published on wordpress.org.

### Form editor

The editor page has a tab bar (`.wp-sjs-editor__tabs .nav-tab[data-tab]`) and panels in `.wp-sjs-editor__columns`. SurveyJS Forms' tabs: `survey` (Config — JSON editor), `theme` (Theme — JSON editor), `email`, `entries`, `spam`, `resume`. `survey`/`theme` show the JSON pane `#wp-sjs-json-pane` (Monaco); any other tab shows the element with the matching `data-panel` and hides the JSON pane. The preview `.wp-sjs-editor__preview` is always on the right. The root `.wp-sjs-editor` has `data-active-tab="<tab>"`, so CSS can change the layout per tab.

**`surveyjs_editor_tabs`** (filter) — `( array $tabs, object $survey )`, `$tabs` is `slug => label` in display order. Add, rename, reorder or remove tabs. The first tab is active on load (`?tab=<slug>` opens another non-JSON tab). Removing `survey` and `theme` removes the JSON editing from the UI (the JSON pane stays in the DOM, hidden, and still holds the JSON that is saved).

**`surveyjs_render_editor`** (action) — `( object $survey )`. Fires inside `.wp-sjs-editor__columns`, after SurveyJS Forms' panels and before the preview. Output one element per added tab:

- `data-panel="<tab slug>"` and `hidden` (SurveyJS Forms shows it when its tab is active). Use `class="wp-sjs-editor__settings"` for a settings panel with SurveyJS Forms' styling.
- Inputs with `data-setting="<key>"` are per-form settings: SurveyJS Forms fills them from the stored settings on load, includes them in dirty tracking and sends them with Save (see "Per-form settings"). Checkboxes store booleans (or `data-checked-value` / `data-unchecked-value`); a hidden input with `data-setting-type="json"` stores a JSON value (SurveyJS Forms uses it for the `webhooks` and `integrations` lists). `data-enabled-by="<setting> [<setting>…]"` on a row disables its controls while none of those checkbox settings is on.

```php
add_filter( 'surveyjs_editor_tabs', function ( $tabs ) {
    return array( 'designer' => __( 'Designer', 'surveyjs-forms-addon' ) ) + $tabs;
} );
add_action( 'surveyjs_render_editor', function ( $survey ) {
    echo '<div class="wp-sjs-addon-creator" data-panel="designer" hidden><div id="wp-sjs-addon-creator"></div></div>';
} );
```

Full-width panel without the preview:

```css
.wp-sjs-editor[data-active-tab="designer"] .wp-sjs-editor__columns { grid-template-columns: minmax(0, 1fr); }
.wp-sjs-editor[data-active-tab="designer"] .wp-sjs-editor__preview { display: none; }
```

#### JavaScript API (`window.surveyjsEditor`)

Defined by `editor.js` (handle `SurveyJS_SurveyJS::EDITOR_SCRIPT`, in the footer). Scripts that depend on that handle can use it directly; otherwise listen to `surveyjs:editor-ready`.

| Member | Description |
|---|---|
| `config` | The editor config: `id`, `name`, `json`, `theme`, `settings`, `saveUrl`, `saveNonce`, `previewUrl`, … |
| `getSurvey()` / `getTheme()` | Current survey / theme JSON object, or `null` while the JSON is invalid. |
| `setSurvey(json)` / `setTheme(json)` | Replace the survey / theme JSON (undoable in the JSON editor), refresh the preview and the lint, mark the form changed. Returns `false` if `json` is not an object. Does not save. |
| `getSettings()` | Current per-form settings from all `data-setting` inputs. |
| `getActiveTab()` / `switchTab(slug)` | Active tab; switch tabs (JSON tabs only after the JSON editor loaded). |
| `isDirty()` | Unsaved changes (name, survey, theme or settings). An AI draft loaded into the editor counts as unsaved. |
| `hasAiDraft()` | Whether the editor holds an AI draft that is not saved yet (see "AI connection (MCP)"). |
| `getSnapshot()` | What the editor shows now, `{ name, json, theme, settings }`, or `null` while the JSON has errors. Fires `surveyjs:editor-flush` first, so Survey Creator pushes its JSON. Used by the AI chat. |
| `applyAiDraft( draft, content? )` | Loads an AI draft (`SurveyJS_AI_Drafts::editor_config()['draft']`, or `null` for none) and shows `content` (or the draft, or the saved form) without reloading the page, then fires `surveyjs:editor-external-change`. |
| `hasEditsAfterAi()` | Whether the person edited the form after the AI draft was loaded. |
| `setAiBusy( busy )` | While true, AI drafts reported by the Heartbeat don't show the "An AI app changed this form" notice. |
| `settingLabel( key )` | The editor's label of a form setting: the tab and the row heading, e.g. `Email: Send To`, or the tab alone for a setting without a row (`webhooks` → `Integrations`). |
| `save()` | Same as the Save button: saves survey, theme and settings in one request. |
| `addSaveCheck( check )` | `check()` runs before every save; a non-empty string it returns stops the save and is shown as "Save failed: …". SurveyJS Forms' integrations use it for the consent check. |
| `getIssues()` | The SurveyJS linter findings of the current survey JSON, `[{ ruleId, severity, message, path }]`, or `null` while the JSON is invalid. Save sends them with the form (`Issues`), the AI chat with each message; AI tools read them back while the JSON is unchanged. |
| `setLintOptions( options )` | Lint options for the editor's checks (`SurveyLinter.lintSurvey( json, options )`): the Static analysis panel, `getIssues()` and "Form saved with N issues". The add-on passes `SurveyCreatorCore.getCreatorLintOptions( creator )`, so the count matches Creator's JSON Editor tab. |
| `isFullPreviewOpen()` | Whether SurveyJS Forms' full preview is open. |
| `setPreviewShowInvisibleElements(show)` | Show questions, panels and pages hidden by `visible` / `visibleIf` in the preview and the full preview (`survey.showInvisibleElements`), until set back. Not saved. |

Events on `document`: `surveyjs:editor-ready` (`detail` = the API), `surveyjs:editor-tab` (`detail.tab`), `surveyjs:editor-saved` (`detail`: `id`, `json`, `theme`, `settings`), `surveyjs:editor-settings-filled` (the settings inputs were filled again, e.g. from an AI draft; the integration and webhook lists re-render), `surveyjs:editor-review-issues` (cancelable, `detail.path` = linter path of the first issue; fired by "Review and fix" in the "Form saved with N issues" notice; without `preventDefault()` SurveyJS Forms opens its Config tab at the issue, the add-on opens Creator's JSON Editor tab at it), `surveyjs:ai-chat-ask` (`detail.text`; the form editor's AI chat opens and sends the text, used by "Fix with AI").

Creator integration sketch: on `creator.onModified` call `surveyjsEditor.setSurvey(creator.JSON)`; on theme changes `setTheme(...)`; load with `creator.JSON = surveyjsEditor.getSurvey()`; on `surveyjs:editor-tab` re-read JSON if the user edited it in the JSON tab. SurveyJS Forms' Save button, unsaved-changes prompt and preview keep working.

### Per-form settings

Per-form settings are one JSON object in the post meta `_sjs_settings` of the form. `SurveyJS_Form_Settings::get( $form )` returns stored values merged over defaults; only keys present in defaults are returned.

**`surveyjs_form_settings_defaults`** (filter) — `( array $defaults )`. Add your keys with defaults. Prefix them (e.g. `addonPdfPaperSize`) to avoid clashes with SurveyJS Forms keys.

**`surveyjs_form_settings_sanitize`** (filter) — `( array $sanitized, array $input )`. Fires whenever settings are sanitized for saving (editor Save, test email, imports). `$input` is the raw input merged over defaults, so your keys are always present. Return `$sanitized` with your keys sanitized; keys not in defaults are dropped.

When the editor saves, stored keys that no plugin declares right now (e.g. The add-on's while the add-on is inactive) are kept, so deactivating the add-on does not lose its per-form settings.

```php
add_filter( 'surveyjs_form_settings_defaults', function ( $defaults ) {
    return $defaults + array( 'addonPdfPaperSize' => 'a4' );
} );
add_filter( 'surveyjs_form_settings_sanitize', function ( $sanitized, $input ) {
    $sanitized['addonPdfPaperSize'] = in_array( $input['addonPdfPaperSize'], array( 'a4', 'letter' ), true ) ? $input['addonPdfPaperSize'] : 'a4';
    return $sanitized;
}, 10, 2 );
$paper = SurveyJS_Form_Settings::get( SurveyJS_Forms::find( $form_id ) )['addonPdfPaperSize'];
```

**`surveyjs_editor_email_rows`** (action) — `( string $context, object $survey )`. Adds settings to the Email tab. `notification` and `auto_reply` fire at the end of the email notification and auto-reply `<table class="form-table">` (output `<tr>` rows; use `data-enabled-by="notificationEnabled"` / `"autoReplyEnabled"`), `end` fires after the auto-reply group (output whole blocks, e.g. an `<h2 class="title">` and a table). Inputs work as in `surveyjs_render_editor`.

**`surveyjs_results_views`** (filter) — `( array $views, object $survey )`, `slug => label`, default `array( 'entries' => 'Entries' )`. The first view is the default; others are opened with `&view=<slug>`. URL of a view: `SurveyJS_Results::view_url( $survey, $slug )`; current view: `SurveyJS_Results::current_view( $survey )`.

**`&entry=<id>`** — the Entries view shows only that entry (any status) and opens it in the view popup on load (which marks it read). Link to one entry: `admin.php?page=surveyjs_results&id=<form>&entry=<id>`.

**`surveyjs_render_results_view`** (action) — `( string $view, object $survey )`. Fires inside `.wrap` after the header and tabs when the current view is not `entries`. **`surveyjs_results_title_actions`** (action) — `( object $survey, string $view )`. Fires right after the "Export CSV" button; print more `<a class="page-title-action">` buttons (e.g. "Export all as PDF").

**`surveyjs_entry_row_actions`** (filter) — `( array $actions, object $item, int $form_id )`. Row actions under the entry ID (`view`, status actions, `delete`). `$item`: `id`, `status`, `user_id`, `ip`, `created_at`, `last_page`, `kept`, `unfinished`, `data` (answers array). Point links to your own handler (e.g. `admin-post.php?action=surveyjs_addon_entry_pdf&form=…&entry=…` with `wp_nonce_url()`) and check the nonce and `SurveyJS_SurveyJS::CAPABILITY` there.

**`surveyjs_entries_bulk_actions`** (filter) — `( array $actions, string $status, int $form_id )`. Bulk actions of the entries table for the current status filter (`''` = All, `unread`, `read`, `partial`, `spam`).

**`surveyjs_entries_bulk_action_{$action}`** (action) — `( int[] $ids, object $survey, string $results_url )`. Fires on `load-` of the results page when your bulk action is submitted, after SurveyJS Forms checked the capability and the `bulk-results` nonce. ### Read API (forms and entries)

Forms (`SurveyJS_Forms`): `find( $id )` (published form or `null`), `get( $id )` (also resolves pre-3.0 form IDs), `all()`, `names()` (`id`, `name` only), `update( $id, array( 'name' | 'json' | 'theme' | 'settings' => string ) )`. A form object has `id`, `name`, `json` (survey JSON string), `theme` (JSON string), `settings` (JSON string). Decode JSON with `SurveyJS_Client::decode_survey_json( $raw, $assoc = true )`.

Entries (`SurveyJS_Entries`):

- `query( $form_id, $args = array() )` — entries of a form, newest first. `$args`: `status` (string or array, default `array( 'unread', 'read' )` — submitted entries; all: `SurveyJS_Entries::STATUSES`), `ids` (int[]), `after` / `before` (UTC `Y-m-d H:i:s`, `>=` / `<` on `created_at`), `order` (`DESC`|`ASC`), `limit` (0 = all), `offset`. Returns objects: `id`, `form_id`, `status`, `user_id`, `ip`, `created_at` (UTC), `last_page`, `kept`, `data` (answers array keyed by question name). Page with `limit`/`offset` on large forms.
- `find_entry( $form_id, $id )` — one entry of any status, or `null`.
- `counts( $form_id )` — `status => count`. `statuses()` — `status => label`; `status_label( $status, $last_page )`; `format_date( $created_at )` — site date/time format.

Form views and submissions (`SurveyJS_Form_Stats`, table `{prefix}sjs_form_stats`, one row per form per site-local day: `form_id`, `stat_date`, `views`, `submissions`):

- `enabled()` — the Form views setting (SurveyJS Forms > Settings, on by default). The add-on checks `class_exists( 'SurveyJS_Form_Stats' )` first.
- `totals( $form_ids, $since = '', $until = '' )` — `form_id => (object) { views, submissions }`; `$since` / `$until` are site-local `Y-m-d`, inclusive / exclusive.
- `timeline( $form_ids, $since, $unit = 'day' )` — `bucket => (object) { views, submissions }`, buckets `Y-m-d` (`day`) or `Y-m` (`month`).
- `conversion( $views, $submissions )` — percent or `null` without views; `format_conversion( $views, $submissions )` — `"12%"`, `"8.5%"` (one decimal below 10%), or `"—"`.
- A view is counted by `survey.js` once per page load when the form is on screen in a visible tab (`IntersectionObserver`), with `navigator.sendBeacon` to `admin-ajax.php?action=surveyjs_form_view` (POST `id`, no nonce, so cached pages keep counting). A submission is counted on `wp_surveyjs_save_result`, also when entries are not stored. Not counted: users with `edit_posts`, bots (empty or known bot user agent, `navigator.webdriver`), GET requests, previews. No cookies, storage, IP or user agent is stored.
- **`surveyjs_count_form_views`** (filter) — `( bool $count, int $form_id )`, default `enabled()`. Return `false` to stop counting views and submissions of a form.

Questions and values (`SurveyJS_Survey_Values`): `survey_questions( $json_array )` — flat list of questions (`name`, `title`, `type`, …); `question_title( $question )`; `display_value( $question, $value )` — answer as text. File answers: `SurveyJS_Uploaded_Files::with_admin_urls( $data )` replaces stored file references with admin download URLs.

### Front-end form

**`surveyjs_form_client_config`** (filter) — `( array $config, object $survey, array $settings )`. The config of a form on the site (`id`, `json`, `theme`, `themeMode`, URLs and nonces, …), printed as JSON next to the form and passed to the JS events below as `detail.config`. Add your own prefixed keys. `locale` is the site language (`survey_locale()`): when the form JSON has no `locale`, `survey.js` sets it, so the Form Library buttons and messages are in the site language; the form preview does the same.

**`surveyjs_enqueue_form_assets`** (action) — `( object $survey, array $settings )`. Fires after SurveyJS Forms enqueued a form's scripts and styles, on `wp_enqueue_scripts` for forms in the post content and again when a shortcode or block renders (so possibly more than once per form, and after `wp_head`: enqueue scripts in the footer).

JS events on `document` (`assets/survey.js`), `detail`: `id`, `survey` (the `Survey.Model`), `config`, `container` (`.wp-sjs-survey`), `data` (answers being sent):

- `surveyjs:before-submit` — right before the entry is sent (after CAPTCHA; before the wait for the minimum time to submit, when it is on). Add request fields to `detail.fields`, or call `detail.waitUntil( promise )` with a promise of an object of fields (rejections are logged and ignored; the submit waits, so settle it in a few seconds). Values are strings or `Blob`s; with a `Blob` the request is `multipart/form-data` and the file is in `$_FILES`. SurveyJS Forms' own fields win over yours.
- `surveyjs:submitted` — after the server accepted the entry; `detail.response` is the `data` of `surveyjs_save_result_response`, or `null`. With CAPTCHA it fires before the completed page is shown.

**`surveyjs_save_result_response`** (filter) — `( array $response, object $survey, int $entry_id, array $data )`, default `array()`. Fires at the end of the save request (after the emails and `wp_surveyjs_save_result`); a non-empty array is sent with `wp_send_json_success()`. `$entry_id` is `0` when entries are not stored.

### Emails

**`surveyjs_notification_tags`** (filter) — `( array $tags, string $recipient, object $survey, array $data, int $entry_id )`. Mail tags of the email notification (`$recipient` `owner`) or the auto-reply (`respondent`): `array( 'text' => array( '{tag}' => value ), 'html' => array( '{tag}' => escaped HTML ) )`, used for plain-text and HTML messages; the subject and From name use the respondent's text tags. Add the same key to both.

**`surveyjs_notification_attachments`** (filter) — `( array $attachments, string $recipient, object $survey, array $settings, array $data, int $entry_id )`. `file name => path` of the email notification (`owner`) or the auto-reply (`respondent`). SurveyJS Forms puts local paths there (files on a stream wrapper are first copied to a temporary file); a path you add on a stream wrapper (`vip://`, `s3://`) is copied the same way, since PHPMailer refuses such paths. Keep the total under `SurveyJS_Notification::MAX_ATTACHMENTS_SIZE`.

### Webhooks

Webhooks are the per-form setting `webhooks`, a list (`id`, `name`, `enabled`, `url`, `headers` — `name`/`value` pairs —, `conditions`), edited on the form editor's Integrations tab below the integrations (`?tab=webhooks` opens it). Each active webhook whose conditions match the answers gets a POST request with a JSON body, sent through the delivery queue (below) right after the submission and retried after 5 minutes and after 1 hour; headers `X-SurveyJS-Event`, `X-SurveyJS-Delivery` and the webhook's custom headers. Body: `event` (`entry.submitted` or `test`), `form`, `entry` (`id`, `submitted_at`, `url`), `site`, `answers` (question name → answer text), `data` (raw answers, file `content` = signed download link), `fields` (`name`, `title`, `text`).

**`surveyjs_webhook_payload`** (filter) — `( array $payload, object $survey, array $data, int $entry_id )`. The JSON body of webhooks only (integrations build their requests from the unfiltered `SurveyJS_Webhooks::snapshot()`); built once per entry, so retries send the same body.

**`surveyjs_webhook_timeout`** (filter) — `( int $seconds )`, default `10`.

Requests go through `wp_safe_remote_post()`, and every address of the host must be public; to allow a host in a private network use WordPress's `http_request_host_is_external` and `http_allowed_safe_ports` filters.

### Integrations

Integrations send each entry to an account connected on SurveyJS Forms > Settings > Integrations (`SurveyJS_Connections`, option `surveyjs_connections`; keys encrypted with libsodium, never shown to the browser or the AI). The per-form setting `integrations` is a list: `id`, `name`, `enabled`, `service`, `connection` (a connection id, never a key), `conditions`, plus the service's own fields. All integrations live in SurveyJS Forms (Slack with an incoming webhook URL, Mailchimp with an API key; new services are files in SurveyJS Forms `integrations/services/`); the add-on adds none. Delivery goes through the delivery queue and is retried after 5 minutes, 1 hour and 6 hours; 401/403 mark the connection "Needs attention".

**`surveyjs_integration_services`** (filter) — `( SurveyJS_Integration_Service[] $services )`. For third-party add-ons: add instances of your services; read once all plugins are loaded. A service extends one of:
- `SurveyJS_Integration_Chat_Service` — a chat app with an incoming webhook URL (Discord, Microsoft Teams, Google Chat): `id()`, `label()`, `description()`, `help_html()`, `url_pattern()`, `url_prefix()`, `message( $title, $text, $entry_url, $context )` (the JSON body), `text_message( $text )`; optional `escape()`, `field_line()`, `format_help()`, `outcome( $code )`. The form editor needs no script of its own.
- `SurveyJS_Integration_Contacts_Service` — an email marketing service with an API key (Brevo, ActiveCampaign, MailerLite): `credentials_from( $input )`, `account( $credentials )`, `lists( $credentials )`, `fields( $credentials, $list )`, `subscribe( $credentials, $feed, $contact )` with `json_request()`; optional `credential_fields()`, `list_label()`, `fields_label()`, `supports( $feature )`, `error_message()`. The editor's "contacts" script loads the lists (a single connection or list is chosen for the person) and maps the fields. Consent is built in: such an integration is not saved without a condition unless its `signupForm` ("This form is a newsletter signup") is on, and the card has a button that adds a "Subscribe me to the newsletter" checkbox with the condition.
- `SurveyJS_Integration_Service` — anything else: `connect()`, `deliver( $feed, $credentials, $payload )` returning `ok`, `code`, `error`, `outcome` (`ok`, `retry`, `reauth`, `permanent`), `retry_after`, `note`; `feed_defaults()`, `sanitize_feed()`, `feed_schema()` (told to the AI), `render_feed_rows()` (table rows with `data-field` inputs and `__KEY__` in ids), `render_rows_after_conditions()`, `feed_error( $feed )` (a message refuses the form's save: in the editor, in the save request and in AI writes), `targets()` (lists the editor loads through `SurveyJS_IntegrationTargets`). Its editor script registers with `window.surveyjsEditorItems.integrations.register( id, { renderExtra( item, node, commit ), onRefresh( item, node ), onFieldChange( item, node, field, commit ), onAction( action, button, item, node, commit ), error( item ) } )`.

Integrations of a service that is not registered now (its add-on is inactive) are kept as stored when the form is saved, and send nothing.

**`surveyjs_integration_timeout`** (filter) — `( int $seconds, string $service_id )`, default `15`.

### Delivery queue

Webhooks and integrations share `SurveyJS_Delivery_Queue`: jobs wait in non-autoloaded options `surveyjs_delivery_queue_<due time>_<key>`, and one WP-Cron event `surveyjs_deliver` (no arguments) sends every due job and schedules itself for the next one. The log of a form is the option `surveyjs_delivery_log_<form_id>` (last 30 attempts, `type` `webhook` or `integration`); a failed entry that is not retried any more can be sent again from the log (`SurveyJS_ResendDelivery`). Deactivation deletes every queued job.

### AI connection (MCP)

SurveyJS Forms registers its abilities (Abilities API, WordPress 6.9+) in the category `surveyjs` while the AI connection is on (option `surveyjs_ai_enabled`) or the AI chat is available (WordPress 7.0+ AI Client, not turned off with `surveyjs_ai_chat_disabled`). It serves every ability of that category on its own MCP server `/wp-json/mcp/surveyjs` through the MCP Adapter plugin; while the AI connection is on, tools are also listed by the adapter's default server (`meta.mcp.public`), so its discovery tool finds them. The Abilities REST API never lists them (`meta.show_in_rest` is false). Abilities whose `annotations.readonly` is false refuse to run unless "Enable MCP write access" is on (option `surveyjs_ai_write`), except inside the AI chat, which may change only the open form. Tools without an input schema get an empty object schema, so MCP clients may send `{}`.

Events of the form editor: `surveyjs:editor-flush` (before the AI chat reads the editor; the add-on pushes Survey Creator's JSON) and `surveyjs:editor-external-change` (after the chat or Undo replaced the editor content; the add-on reloads Survey Creator from the editor).

**`surveyjs_ai_register_abilities`** (action) — fires inside `wp_abilities_api_init` while the AI connection is on. Register abilities with **`SurveyJS_AI_Abilities::register_ability( $name, $args )`**: it sets the category, a `manage_options` permission check and the MCP meta (`meta.mcp.type` `tool` by default, `resource` or `prompt` when set). Rules for abilities on this server: no access to entries, nothing deletes data; form changes go through `SurveyJS_AI_Drafts::save( $form, $changes )` so a person saves them in the form editor; start descriptions of read tools with what they return and end them with `SurveyJS_AI_Abilities::DATA_NOTICE`.

**`surveyjs_ai_form_settings_schema`** (filter) — `( array $schema )`, `key => array( 'type', 'default', 'description', 'enum'? )` for every per-form setting, returned by `surveyjs-get-form-settings`. SurveyJS Forms builds the types and defaults from `surveyjs_form_settings_defaults`; add descriptions and allowed values of your keys.

**`surveyjs_ai_read_only_form_settings`** (filter) — `( string[] $keys )`. Keys an AI app can't change (SurveyJS Forms: entry retention, because it deletes entries).

**`surveyjs_ai_sensitive_form_settings`** (filter) — `( string[] $keys )`. When an AI draft changes one of these keys, the form editor warns that the AI changed who receives emails or what they include (SurveyJS Forms: recipients, Reply-To, attachments, auto-reply). SurveyJS Forms also warns, separately, when the AI changes a webhook's `enabled`, `url`, `headers` or `conditions` (and says so when a webhook URL is new), and when it changes any field of an integration but its name.

**`surveyjs_ai_secret_values`** (filter) — `( string[] $values )`. Exact values replaced with `[hidden]` in everything an ability returns (SurveyJS Forms: the CAPTCHA secret key, the Akismet key, connector API keys, SMTP passwords from constants, every form's webhook header values and the keys of every integration connection). Webhook header values are also always `[hidden]` in form settings; when the AI sends `[hidden]` back for a header with the same name in a webhook with the same `id` and URL, the stored value is kept. A webhook whose URL the AI changes gets no stored header values. Any other write that contains `[hidden]` is refused.

Other filters: `surveyjs_ai_question_types` (question types the JSON check accepts besides the built-in ones), `surveyjs_ai_instructions` (the MCP server instructions), `surveyjs_ai_docs_server_url` (the SurveyJS documentation MCP server), `surveyjs_ai_plugin_guide` (the plugin guide served by `surveyjs-get-plugin-guide` and `surveyjs://guide/plugin`; the add-on appends its features), `surveyjs_ai_chat_abilities` (abilities the AI chat may call), `surveyjs_ai_chat_system_instruction`, `surveyjs_ai_chat_providers` (provider rows of the chat checklist).

The add-on (`includes/ai.php`) adds `surveyjs-forms-addon/get-settings` and `surveyjs-forms-addon/update-settings` (Creator, color mode, Creator style), descriptions of the `addonPdf*` form settings, and marks PDF attachments and PDF links in emails as sensitive.

## Development

- Demo: `../../demo` (`docker compose`), http://localhost:9876. The repo is bind-mounted to `wp-content/plugins/surveyjs-forms-addon`.
- Libraries: `npm install && npm run copy-libs`, commit `libs/`.
- Tests: `npx playwright test --project=setup --project=e2e` (reads `../../demo/.env`; set `WP_CONTAINER=demo-wordpress-1` for the tests that run PHP in the container: the SurveyJS Forms-inactive notice and the contract tests). The first login after a container restart can time out — rerun.
- Zip: `git archive --format=zip --prefix=surveyjs-forms-addon/ -o surveyjs-forms-addon.zip HEAD`.
- Updates: test site http://localhost:9905 (`../../sandboxes/pro-update-test`, SurveyJS Forms and the add-on are copies in a Docker volume): `reset.sh` copies this working tree as an older add-on and offers a bumped SurveyJS Forms from `git/surveyjs-wordpress/src/trunk` as an update.
- Before release: `npm run make-pot`; Plugin Check and `phpcs --standard=WordPress-VIP-Go` must be clean.
